# Feature List — Bouncing Forward

> Everything the site does, one plain-English line each. **Everything on this list gets tested; nothing off this list does.** Drafted by Claude Code from a full scan of the code plus the predevelopment docs; approved by the owner before any test is written.

- Source scan date: 10 September 2026 (draft v3 — refresh of the 9 September draft after the harness PR merged) · Repo head: `07ef8c3bc983fa3db9bedbf19613c345dfc15842` (= `main`; PR #36 merged 9 September 2026 with the testing harness, reset/contact/Stripe fixes, sitemap correction and Google verification file). Production has served this exact commit since 9 September 2026 (observed read-only on 10 September).
- Live site: `https://www.bouncing-forward.com` (the address without `www` redirects there; `bouncing-forward.vercel.app` still answers directly and is recorded as Production too).
- Test users (non-production only, TEST Supabase project `hmcojplrqoqhyigvtgyp`): two plus-addressed identities on the owner's own mailbox so reset and confirmation emails can be received — `<owner-mailbox>+bf-e2e-free@gmail.com` (account, no Book Package) · `<owner-mailbox>+bf-e2e-premium@gmail.com` (account that owns the Book Package). The base mailbox is stored only as `E2E_OWNER_MAILBOX`; the full addresses as `E2E_FREE_USER_EMAIL` / `E2E_PREMIUM_USER_EMAIL`; passwords only as `E2E_FREE_USER_PASSWORD` / `E2E_PREMIUM_USER_PASSWORD`. **Both accounts exist in the TEST project since 9 September 2026** (created by the owner with the bootstrap tool; the premium account's Book Package entitlement was added through the approved TEST connection) and both signed in on the Preview that day. There is no admin role anywhere in the code, so no admin user.
- Shared services (owner decision, 9 September 2026): Mailchimp audience, Formspree form and the legacy access codes are the **same** in Preview and Production. They are recorded as shared, not isolated. Tests touching them use only controlled test identities and clearly labelled test messages, one at a time, with recorded cleanup; nothing high-volume ever runs against them.
- **Owner approval: approved by the owner in chat on 10 September 2026** ("ok feature list approved", in reply to draft v3; recorded by Claude Code). From here on, any change to a line goes back to the owner — see the change log.

**How to read a line:** `ID | Who can do what | What proves it worked`. If a plain-English line here is wrong or missing, the tests will be too — this list is where your ten minutes matter most.

**Honesty markers used below:**

- **EXPECTED FAIL** — the site does not currently do this; the line stays on the list so the gate cannot go green until it is fixed or you decide otherwise.
- **FIXED IN CANDIDATE** — the fix shipped with the harness PR (#36, merged into `main` and live on Production since 9 September 2026) but no test has proven it yet; the line passes only once the suite proves it on the Preview.
- **SHARED** — touches a service shared with Production; runs once per run with a labelled test identity and needs manual cleanup/evidence.
- **MANUAL** — real, but a human has to verify it; evidence is recorded like any other result.
- **(found in code, not in docs)** — built, but no approved document describes it.
