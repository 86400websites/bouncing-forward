## Deviations and learnings

- The multi-agent workflow (7 planners → harness + hooks → writers → two-lens reviewers → critic) hit the subagent session limit twice. The seven section plans, the harness modules and the one test hook came from agents; every spec was written by the operator from those plans, so the two-lens adversarial review did not run — the independent Codex review carries that weight.
- Tool limits learned: the Bash tool truncates commands above roughly 8 KB and collapses doubled backslashes; long files were written in parts and regexes kept backslash-free. A workflow resume only accepts a script path inside the working directory.
- Dry-run fixes to the harness, not the site: `getByText` needs `exact: true` where a phrase recurs inside a paragraph; the desktop menu opens on hover (a click toggles it closed); Next streams the metadata of dynamic pages into the body, so `<title>` and `og:*` are parsed from head then body; a visitor's `/account` can be a streamed 200 carrying only the client redirect; the Full Assessment gate field is `#fa-email` (two "Email address" labels on the page); the `api` fixture inherited a file-level `storageState` until pinned.
- Five lines are asserted as the code behaves, with annotations and notes for the owner (no line edited): AC-003f uses a superseded reset token as the closest robot equivalent of "expired"; PR-002 runs a bounded probe the server rejects before Mailchimp is called; PY-013 asserts the deliberate 500 "Stripe will retry" for a wrong-mode event; PY-015 asserts "Payment received — opening now." at the success address; FM-005's fallback half re-upserts the FM-002 member once.
- FM-011 (Blocker) was found by the scan and its test written; the owner asked for assurance before any fix. The fix is a two-value allow-list on the `source` field of `/api/newsletter`; the Book Package tag is applied by the payment webhook through a different path, so the fix cannot touch purchases. It ships as its own small PR, proven by FM-002, FM-006, FM-010 and FM-011 on its Preview. Until then every full run tags the `tagprobe` identity `premium` once and the owner receives the access-code email (black it out in evidence).
- A full run writes real test data on the Preview: three $9.99 test-mode purchases (PY-001, PY-010 ×2), premium-tagged test contacts in the shared Mailchimp audience (buyer, buyer-legacy, buyer-paymentlink, tagprobe), one labelled contact message, throwaway TEST accounts — all registered for the `cleanup` project; the owner's inbox receives the journey emails.
